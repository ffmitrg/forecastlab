# Agent 6：别把合理的审查意见删掉

本次贡献：吴懿高，负责⑥审查结果处理、回归评测和处理记录。代码、测试与文档由 Codex 协助完成。

这次先处理一个具体问题。信息截至日是 9 月 26 日时，“缺少截至日前已公布的 10 月 1 日发布计划文件”是合理质疑，但原逻辑看到未来日期就可能把它删掉，还把 `blocked` 改成 `qualified`。计划文件今天可能已经存在，和未来才知道的实际结果不能混在一起。

## 改了什么

在 `backend/app/review_policy.py` 单独放审查规则，由 `graph.py` 的 `review_node` 调用。只有整条意见都明确在索要未来实际结果时才删除；计划文件、事实错误、混合意见和含糊表达都保留。删掉一条意见，也不能顺带解除其他原因造成的阻断。

原始审查、每条意见的保留/删除理由、处理前后状态和证据复审结果都会保存。在导出的 JSON 中看 `stage_outputs.review.review_policy_audit`。页面仍展示处理后的审查意见，暂时没有新增面板。

原有 `evidence_only` 回退保留：推演有问题时可以继续是 `blocked`，但独立证据审查通过后，仍可只用外部证据估计概率。世界状态中的未来措辞只能触发这次复审，不能用来删意见或解除阻断。没有新增模型角色；复审触发次数可能变化，所以不保证每次调用量完全相同。

## 怎么看见区别

在仓库根目录运行：

```bash
uv run python eval/review_policy.py --case D03
uv run python eval/review_policy.py
uv run pytest -q
```

D03 会显示同一条计划文件意见从旧版 `drop / qualified` 变成新版 `keep / blocked`。
